# Speak in YOUR voice (Cairo-TTS) - all-in-one, nothing to configure

The default voice is **`chat/voice/my-voice.wav`** (the sample you gave). Cairo-TTS clones it and speaks every comment reply
and every script line in it; the mouth is lip-synced from the real audio (`web/lipsync.js`).

## Option A - built into your Railway deploy (default, recommended)
The root `Dockerfile` now installs Cairo-TTS (CPU) inside the same container, downloads the model while building, and
`start.sh` runs it on 127.0.0.1:7860 next to the chat server. `chat/config.js` finds it automatically (`CAIRO_LOCAL=1`).

1. Push this project to your (private) GitHub repo and redeploy on Railway as before. The first build is slow (several minutes: PyTorch + model).
2. Open `https://YOUR-RAILWAY-URL/voices`: wait until it shows `"up":true` (about a minute after each start while the model loads;
   lines spoken before that use the Edge Egyptian voice).
3. Done. Optional: record a different voice in `publish.html` > Voice > "My voice (clone)" (replaces the default until the next redeploy;
   commit the new `chat/voice/my-voice.wav` to make it permanent).

Needs enough memory (about 2 GB free is comfortable). If Railway shows out-of-memory or the voice is too slow:
set the variable `CAIRO_TTS_QUANTIZE=1` (int8, faster), or use a bigger plan, or Option B.
To build without the voice (smaller and faster, Edge voices only): build argument `WITH_CAIRO=0`.

## Option B - a separate voice service (only if A is too heavy)
Run the `cairo/` folder as its own service (a Hugging Face Docker Space on CPU, or any Docker host), then set in `chat/config.js`:
`VOICETUT_URL: 'https://...'` (and `HF_TOKEN` if the Space is private). An explicit `VOICETUT_URL` overrides the built-in voice.

## Notes
* Only clone a voice you have the right to use. Cairo-TTS's notice forbids impersonation; its weights follow Kyutai Pocket-TTS terms (check commercial use on the model card).
* If the voice is down or slow, a line falls back to the Edge Egyptian voice so the stream never goes silent.
* Testing status: the real `cairo/app.py` was run under uvicorn and driven by the real `chat/voicetut.js` and `server.js`
  (reference upload, cloned + preset synthesis, the 404 re-upload retry, bearer auth, /voices, thread controller) against a
  stand-in for the model, because the build sandbox cannot reach Hugging Face or PyTorch. **Real weights were NOT run there** -
  run `python cairo/validate.py --url http://127.0.0.1:7860` on your instance (below): it uses the library's default
  `CairoTTS.from_pretrained()` path and checks every clip.

## Option C - run it locally on the instance, CPU only, with a thread budget
    bash cairo/run-local.sh                         # venv + CPU torch + service on 127.0.0.1:7860
    CAIRO_NUM_THREADS=3 bash cairo/run-local.sh     # pin the threads (default: usable cores - 1 when >= 4 cores, else all)
    VOICETUT_URL=http://127.0.0.1:7860 node chat/server.js
or `docker compose --profile cairo up -d` (container limited by `CAIRO_CPUS`, default 2) with `VOICETUT_URL=http://cairo:7860`.
The budget respects Docker/Railway CPU quotas (cgroup), not just the host core count. Change it live, no restart:
    curl -X POST localhost:7860/threads -H 'Content-Type: application/json' -d '{"n":2}'     (add -H "Authorization: Bearer $VOICETUT_TOKEN" if set)
    curl localhost:7860/health          # shows threads + usable_cores
Find the best number: `python cairo/validate.py --threads 1 2 4` prints the x-real-time for each. Leave 1 core for the chat server.

## Voice faults fixed in this build
* The reference `chat/voice/my-voice.wav` began with ~1.4 s of faint babble, a 0.4 s gap, then the sentence (~11 dB louder). A clone copies
  its prompt, so cloned lines inherited it. The service now cleans every uploaded reference (drops the faint lead-in, trims silence)
  and also removes such a lead-in from generated audio (`CAIRO_GHOST_DB`, default 9 dB; 0 turns it off). Both are logged as
  `dropped ... faint lead-in`. Best fix: record a fresh 8-10 s reference with no pause at the start.
* That file's name (`cairo-tts-...wav`) suggests it was generated by Cairo-TTS itself, not recorded by you. If so, the "clone" copies
  a synthetic voice; for YOUR voice, record it in publish.html > Voice > "My voice (clone)".
